## 1. Описание предметной области

Рассматривается информационная система института, предназначенная для централизованного хранения и обработки сведений об организации учебного процесса.

**Решаемая проблема.**
Сведения об учебном процессе (студенты, группы, дисциплины, преподаватели, результаты аттестации) хранятся разрозненно — в бумажных журналах, таблицах и локальных файлах. Из-за этого:
- сложно быстро получить актуальную информацию о результатах студента;
- данные дублируются и могут противоречить друг другу;
- нет единого разграничения доступа по ролям;
- затруднён контроль успеваемости и учебной нагрузки.

**Цель системы.**
Разработать информационную систему для централизованного хранения и обработки сведений об организации учебного процесса, обеспечивающую разграничение доступа по ролям и оперативный доступ к результатам обучения.

**Область применения.**
Деканат, кафедры, преподаватели, студенты. Система используется для ведения учебного процесса, учёта успеваемости и информирования участников.

**Основные сущности.**
Студент, Учебная группа, Образовательная программа, Дисциплина, Преподаватель, Занятие, Учебная работа, Результат аттестации, Пользователь, Роль.

## 2. Пользователи и роли

| Роль | Назначение | Основные функции | Уровень доступа |
|------|------------|------------------|-----------------|
| **Студент** | Просмотр информации о своём обучении | Просмотр своих дисциплин, занятий, учебных работ и результатов аттестации; изменение контактных данных | Только свои данные (чтение) |
| **Преподаватель** | Работа со сведениями о дисциплинах и результатах | Просмотр своих дисциплин, групп, занятий; выставление и редактирование оценок; создание учебных работ; просмотр успеваемости | Данные своих дисциплин и групп |
| **Сотрудник института** | Актуализация данных учебного процесса | Управление студентами, группами, дисциплинами, программами; формирование отчётов; назначение преподавателей | Широкий доступ к справочникам |
| **Администратор** | Управление системой и доступом | Управление пользователями и ролями; настройка прав; резервное копирование; просмотр журнала действий | Полный доступ к системе |

## 3. Сценарии использования

### 3.1. Авторизация в системе
- **Инициатор:** любой пользователь (Студент, Преподаватель, Сотрудник, Администратор)
- **Шаги:**
  1. Пользователь открывает веб-интерфейс системы.
  2. Вводит логин и пароль.
  3. Система проверяет учётные данные.
  4. Система определяет роль пользователя.
  5. Пользователь перенаправляется в личный кабинет с доступными ему функциями.
- **Ожидаемый результат:** пользователь авторизован, ему доступны функции согласно его роли.

### 3.2. Просмотр результатов аттестации студентом
- **Инициатор:** Студент
- **Шаги:**
  1. Студент входит в систему.
  2. Переходит в раздел «Мои результаты».
  3. Выбирает дисциплину или семестр.
  4. Система отображает оценки по видам аттестации.
  5. Студент просматривает данные.
- **Ожидаемый результат:** студент получает актуальную информацию о своих оценках.

### 3.3. Выставление оценки преподавателем
- **Инициатор:** Преподаватель
- **Шаги:**
  1. Преподаватель входит в систему.
  2. Выбирает свою дисциплину.
  3. Выбирает учебную группу.
  4. Выбирает студента из списка.
  5. Указывает вид аттестации и оценку.
  6. Сохраняет результат.
  7. Система фиксирует изменение и записывает действие в журнал аудита.
- **Ожидаемый результат:** оценка сохранена в БД и доступна студенту.

### 3.4. Добавление студента сотрудником института
- **Инициатор:** Сотрудник института
- **Шаги:**
  1. Сотрудник входит в систему.
  2. Переходит в раздел «Студенты».
  3. Нажимает «Добавить».
  4. Заполняет персональные и учебные данные (ФИО, дата рождения, зачётная книжка, группа, форма обучения).
  5. Сохраняет запись.
  6. Система проверяет уникальность номера зачётной книжки.
  7. Студент добавляется в выбранную группу.
- **Ожидаемый результат:** новый студент создан и привязан к группе.

### 3.5. Создание учебной работы преподавателем
- **Инициатор:** Преподаватель
- **Шаги:**
  1. Преподаватель входит в систему.
  2. Выбирает дисциплину.
  3. Переходит в раздел «Учебные работы».
  4. Нажимает «Создать работу».
  5. Указывает вид (КР, реферат, лабораторная), описание и срок сдачи.
  6. Сохраняет работу.
  7. Система делает работу доступной для студентов группы.
- **Ожидаемый результат:** работа создана, студенты видят её и срок сдачи.

### 3.6. Управление пользователями администратором
- **Инициатор:** Администратор
- **Шаги:**
  1. Администратор входит в систему.
  2. Переходит в раздел «Пользователи».
  3. Создаёт нового пользователя или выбирает существующего.
  4. Назначает роль (Студент, Преподаватель, Сотрудник, Администратор).
  5. При необходимости блокирует или разблокирует учётную запись.
  6. Сохраняет изменения.
  7. Действие фиксируется в журнале аудита.
- **Ожидаемый результат:** учётные записи и права актуализированы.

## 5. Компоненты системы

| Компонент | Назначение | Взаимодействует с |
|-----------|------------|-------------------|
| **Web-интерфейс (Frontend)** | Предоставление UI для всех ролей пользователей | Backend по HTTP/REST |
| **API-сервер (Backend)** | Бизнес-логика, обработка запросов, проверка прав | Frontend, БД, Auth, Reports, Notify |
| **Модуль аутентификации и авторизации** | Вход в систему, проверка учётных данных и прав доступа | Backend, БД |
| **База данных** | Хранение сведений о студентах, группах, дисциплинах, оценках и т.д. | Backend по SQL |
| **Модуль отчётов** | Формирование отчётов по успеваемости и нагрузке преподавателей | Backend, БД |
| **Модуль уведомлений** | Отправка уведомлений (email) о сроках, оценках и событиях | Backend, SMTP-сервис |
| **Журнал аудита** | Фиксация действий пользователей | Backend, БД |

## 6. Диаграмма компонентов

![Диаграмма компонентов](diagrams/architecture.png)

**Описание диаграммы.**

- **Пользователь** взаимодействует с системой через **Web-интерфейс** по HTTPS.
- **Web-интерфейс** обращается к **API-серверу** по REST/JSON.
- **API-сервер** — центральный компонент: проверяет права через **Модуль аутентификации**, читает/пишет в **Базу данных** по SQL, вызывает **Модуль отчётов** и **Модуль уведомлений**.
- **Модуль аутентификации** хранит пользователей и роли в БД, выдаёт токены.
- **Модуль отчётов** формирует выборки из БД и возвращает их API-серверу.
- **Модуль уведомлений** отправляет email через внешний **SMTP-сервис**.
- **Журнал аудита** пишется API-сервером в БД.

## 7. Концепция информационной системы

**Назначение и цель.**
Система предназначена для централизованного хранения и обработки сведений об организации учебного процесса в институте, обеспечения разграничения доступа по ролям и оперативного доступа к результатам обучения.

**Основные возможности.**
- Ведение справочников студентов, групп, дисциплин, преподавателей, образовательных программ.
- Учёт занятий и учебных работ.
- Учёт результатов аттестации.
- Разграничение доступа по ролям.
- Формирование отчётов по успеваемости и нагрузке.
- Долговременное хранение данных в течение всего периода обучения.
- Ведение журнала действий пользователей.

**Тип системы.**
Веб-приложение с клиент-серверной архитектурой (трёхуровневая: клиент — сервер приложений — БД).

**Основные компоненты и их взаимодействие.**
1. **Web-интерфейс** — браузерный доступ, отображение данных по роли.
2. **API-сервер** — бизнес-логика, обработка запросов, проверка прав.
3. **Модуль аутентификации и авторизации** — вход и разграничение доступа.
4. **База данных** — хранение сведений об объектах предметной области.
5. **Модуль отчётов** — формирование отчётности.
6. **Модуль уведомлений** — информирование пользователей.
7. **Журнал аудита** — фиксация действий.

Взаимодействие: пользователь → Web-интерфейс → API-сервер → (Auth / БД / Reports / Notify). Все изменения фиксируются в журнале аудита.

**Результат использования.**
Пользователь получает актуальную информацию в соответствии со своей ролью: студент — свои оценки и задания, преподаватель — данные для работы с дисциплинами и студентами, сотрудник — инструменты управления учебным процессом, администратор — управление системой и доступом.
